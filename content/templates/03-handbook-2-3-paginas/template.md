## Estrutura padrão — Handbook 2-3 páginas

### Página 1 — KPI principal e Definition of Done

```
HANDBOOK · {NOME · MOTION · MOMENTO}

KPI PRINCIPAL
{Métrica única, ex: TTFI ≤ 90 dias}

DEFINITION OF DONE (todos sim)
✓ {critério objetivo 1}
✓ {critério objetivo 2}
✓ {critério objetivo 3}
✓ {critério objetivo 4}

3 MOMENTOS CRÍTICOS
1. {Momento 1 — D+0 a D+X}: {ação principal}
2. {Momento 2 — D+X+1 a D+Y}: {ação principal}
3. {Momento 3 — D+Y+1 a D+Z}: {ação principal}
```

### Página 2 — Cadência e Hand-offs

```
CADÊNCIA TÍPICA ({MOTION})
Semana 1-N — {atividade}
Semana N+1-M — {atividade}
...

HAND-OFFS
{Origem} → {Destino} ({trigger}): {asset transferido}
{Origem} → {Destino} ({trigger}): {asset transferido}

DASHBOARDS CONSULTADOS
- {Dashboard 1}
- {Dashboard 2}
- {Dashboard 3}
```

### Página 3 (opcional) — FAQ e objeções comuns

```
SE O CLIENTE...
... {situação 1} → {ação corretiva}
... {situação 2} → {ação corretiva}
... {situação 3} → {ação corretiva}

OBJEÇÕES COMUNS
"{objeção 1}" → {reframe ou resposta}
"{objeção 2}" → {reframe ou resposta}
"{objeção 3}" → {reframe ou resposta}
```

## Exemplo preenchido — Onboarding High-touch

### Página 1

```
HANDBOOK · ONBOARDING HIGH-TOUCH

KPI PRINCIPAL
Time to First Impact (TTFI) ≤ 90 dias

DEFINITION OF DONE (todos sim)
✓ Cliente bate métrica de sucesso definida na proposta
✓ Health Score ≥ 80
✓ Sponsor confirma valor entregue (e-mail formal)
✓ QBR de 90 dias agendado e realizado

3 MOMENTOS CRÍTICOS
1. Kickoff (D+0 a D+7): definir métrica de sucesso, mapear stakeholders, agendar weekly sync
2. First Win (D+30): primeiro impacto demonstrável, mesmo que pequeno
3. Validation (D+90): QBR com números reais
```

### Página 2

```
CADÊNCIA TÍPICA (HIGH-TOUCH)
Semana 1-2 — Kickoff intensivo (3 reuniões, time completo)
Semana 3-6 — Implementação técnica + treinamento power users
Semana 7-9 — Adoção monitorada (weekly checks)
Semana 10-12 — Validation + QBR

HAND-OFFS
Sales → CSM (D-7 antes do contrato): handoff doc + introdução em call
CSM → Suporte: tickets técnicos saem do CSM
CSM → AE de Expansão (D+90 se Health >80): identificar whitespace

DASHBOARDS CONSULTADOS
- TTFI por cliente (real vs prometido)
- Adoption Score (uso de features-chave)
- Health Score (modelo composto)
- NPS pós-onboarding
```

### Página 3

```
SE O CLIENTE...
... atrasa kickoff por 2+ semanas → escalation para sponsor
... muda decisor durante o onboarding → restart parcial, novo alinhamento
... não atinge first win em D+30 → diagnóstico técnico + plano corretivo
... bate métrica antes do prazo → acelerar Validation, abrir conversa de expansão

OBJEÇÕES COMUNS
"Não temos tempo para treinamento" → reframe via custo de não-adoção
"O time interno resolve" → mostrar gap de produtividade humana medido
"Vamos esperar 6 meses para usar" → custo de oportunidade quantificado
```

## Checklist de qualidade do handbook

- [ ] Cabe em 2-3 páginas (entre 400 e 800 palavras total).
- [ ] KPI principal único e mensurável.
- [ ] Definition of Done com 3-5 critérios objetivos.
- [ ] Owner declarado.
- [ ] Cadência típica documentada por semana ou mês.
- [ ] Hand-offs explícitos (origem → destino com trigger e asset).
- [ ] Dashboards listados.
- [ ] FAQ cobrindo 4-6 cenários e objeções comuns.
- [ ] Revisão trimestral agendada no calendário.
